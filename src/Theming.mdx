# Theming

Relic themes are CSS-variable themes. Components do not hard-code palette
colors. They read semantic tokens such as `--ds-color-bg`,
`--ds-color-primary`, and `--ds-color-text`, then the active theme decides what
those tokens mean.

The color system has two layers:

1. Primitive palette tokens live in `src/styles/tokens.css`. These are raw
   colors like `--ds-palette-gray-950` or `--ds-palette-blue-600`.
2. Semantic theme tokens live in `src/styles/themes.css`. These are role-based
   aliases like `--ds-color-surface`, `--ds-color-border`, and
   `--ds-color-destructive`.

Components should only reference semantic `--ds-color-*` tokens. That keeps the
component API stable while the visual identity changes underneath it.

## How theme switching works

Set `data-theme` on `html` or on any ancestor of the themed UI:

```html
<html data-theme="dark">
  ...
</html>
```

The current Storybook toolbar uses the same mechanism through
`withThemeByDataAttribute` in `.storybook/preview.ts`. The available draft
themes are:

- `yellow`
- `dark`
- `dark-red`
- `white-on-black`

`yellow` is also the default `:root` theme, so the app has a fallback even when
no `data-theme` attribute is present.

## Adding or changing a theme

1. Add or adjust raw color values in `src/styles/tokens.css` when the design
   needs new primitives.
2. Map every required semantic `--ds-color-*` token in
   `src/styles/themes.css`.
3. Register the theme name in `.storybook/preview.ts` so it appears in the
   Storybook theme toolbar.
4. Check components in every theme, especially focus, disabled, destructive,
   and high-contrast states.
